# 1.0.0 公式与绕图排版修订

本修订属于 1.0.0 发布。

## 行内公式

- 依据视觉行、字形和相邻关系合并公式主体、帽子、上下标，以及分散在不同 PDF 文本对象中的片段。
- 完整段落仍作为一个翻译单元；公式以受保护标记传给模型，再复制原始 PDF 矢量内容。
- 使用保留小数的 CSS 尺寸，避免 HTML 图片宽高属性的整数截断。公式按等比例缩放，并根据原始基线调整位置和预留行距。
- 校验公式标记、比例、边界和文字碰撞。无法安全放下时保留原文，译文仍可在校对界面查看。
- 独立公式里的说明性英文单独识别。若说明文字与公式字形的删除范围相交，保留原文并提示校对，避免删除下括号或其他数学符号。

## 图片旁的正文

- 将照片、图表主体及相邻字形作为排版避让区域。
- 同一段译文可以连续排入照片旁边的窄区域及照片下方的宽区域，不拆成多个独立翻译请求。
- 图内标签仍可以在自己的图片范围内翻译；完整扫描页不会被误当成禁止写入的图片。
- 旋转页面保持原方向；水平及 90/180/270 度文字使用对应的局部坐标。遇到无法可靠避让的斜排或竖排区域时保留原文提示核对。
- 导出前检查相邻译文的可见内容是否重叠；失败时保留原文，不截断译文，也不突破最低字号。

## 已有任务如何使用

旧 PDF 不会自动变化，需要用本修订重新导出。

程序首次读取旧的段落任务时，会在本地更新原生文字结构，分析结构版本现为 6。人工校对的原文、译文、方向和保留原文设置优先保留，其余区域重新组合。结构未变化的自动译文复用；结构变化且无法安全转换的区域显示为待校对，旧译文保留为草稿。仅导出时不会调用 AI，也不会把结构不匹配的旧草稿写回 PDF。重试失败也不会绕过此限制。

更新结构本身不调用 API、不重新 OCR、不读取或修改密钥。需要重新翻译的区域仍会消耗正常的接口用量。旧任务原有的手动区域、OCR 标签和用量记录保留。

页码范围变化保留原来所有页面的缓存和累计用量，只处理当前选中页面；新增页没有完成过翻译时才需要新请求。普通字体的常见代数表达式加入矢量公式识别和文本保护。竖排段落中的公式作为完整对象放入列内，不拆解公式标记；无法安全放下时保留原文。导出时重新计算临时排版提示，已解决的溢出提示会清除。详见[五项回归修复](REVIEW_FIXES.md)。

## 验证范围与限制

在用户指定的两篇 PDF 上做了离线排版验证。公式页使用人工准备的完整段落及公式标记作为排版输入；作者介绍页复用现有译文。验证不调用付费 API，不代表重新完成了文献翻译质量评估。

作者介绍页的 5 张照片在 144 DPI 的相同区域渲染中逐像素一致。公式页已检查矢量公式、上下标、基线和段落换行；两处紧贴下括号的说明英文触发保留原文策略。原始 PDF、用户已导出的 PDF、应用密钥和实际任务缓存均未在验证中改写。

复杂扫描件、无法分离的公式字形、弯曲文字或照片与文字已合成同一位图的情况，仍可能需要人工校对。扫描原图本身的模糊不会因本修订获得额外细节。

诊断文件仅保存在本地 `test-output/layout-fix-20261030/`，不会进入公开源码包或 EXE。
