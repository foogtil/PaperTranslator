# 1.1.0 字体删除与表格修复（2026-10-31）

此修订仍为 1.1.0。修复的主要现象是：部分 PDF 写入中文后原英文仍然可见，两种文字严重叠印；表格中的多行数据被排成普通段落。

## 原因与处理

1. **非标准字体度量**：原字框中心不一定落在 PDF 引擎实际用于删除的字体区域内。样本文字字体的上升部比例约为 0.541、下降部为 0；原中心点删除方式会残留正文。现在依据各字形实际基线及方向定位删除点，缓存中的原始字形坐标不改写。
2. **写回前缺少删除结果校验**：现在先在独立页副本上执行同一删除操作。目标字形仍存在或误删了其他字形时，该区域保留原文并列入校对，不再直接叠加译文。该检查在本地执行，无额外 API 请求。
3. **表格被误合并**：根据重复对齐的数值列、显著性标记和行标签拆分单元格；纯数值留在原位，文字在对应单元格内翻译。表格旁另一栏的正文保持为正文，不并入表格。末列标题可利用该列数值的实际宽度。显式覆盖排版库的 body 默认内边距，避免窄单元格及小标题被误判溢出；不降低最低字号。没有足够对齐证据的复杂表格仍需人工校对。
4. **标题和 DOI**：相邻的短标题尾行可与主标题组成同一段；URL、DOI 和邮箱不再被普通字体代数识别拆成公式对象。保护编号、公式和网址的原有规则继续生效。
5. **图内标签的灰色轮廓**：同一图像修补在 300 DPI 看似已擦除，放大后仍可能出现原英文形状的灰边。现在将修补颜色和透明掩膜分别嵌入 PDF，避免 RGBA 图像转换与重采样的边缘灰影；删除范围和轴线保护不扩大。合成回归在 600 DPI 检查文字区域干净且旁边轴线像素不变。

## 已有任务

分析结构版本从 3/4/5 升级到 6，项目 schema 仍为 1。人工修改及用量记录保留；结构、内容和原始字形位置匹配时复用已有译文。公式标签变化仅在原模板能准确还原同一原文时转换缓存。无法匹配的旧表格/标题译文保留为草稿，重新翻译或人工确认后才可写回，避免把整张旧表格译文填到一个单元格。

已有 PDF 需要重新导出。只重新导出不调用 API；必要的新增翻译仍有正常接口用量。此次样本修复复用了已有译文，对新拆分的表格文字及完整标题做了离线校对，并另存修复版；未覆盖用户的原 PDF、已导出的译文或实际任务缓存，未读取保存的密钥。

## 验证

异常字体测试使用自行构造的矩形字形字体，位于 `assets/selftest/metric-font.pdf`，不含论文或第三方字体。覆盖原中心点删除失败、基线删除、0/90/180/270 度及裁剪页、相邻内容保留、删除失败安全回退、表格数字像素不变、相邻栏正文、旧任务升级、DOI 缓存转换、密集单元格最小字号及透明修补边缘。受保护字形用空间索引做精确碰撞检查，避免密集表格反复扫描整页所有数值字形。真实样本诊断保存在本地 `test-output/disease-20261031/`，不进入公开发行包。

这不是对模型翻译准确率的保证。复杂公式、密集表格、低置信度 OCR 或放不下的文字继续保留原文供人工核对。
